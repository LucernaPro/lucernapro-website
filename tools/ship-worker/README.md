# Lucerna Ship — ระบบจัดส่งสำหรับพนักงาน

หน้าเว็บ: `www.lucernapro.com/ship` (theme เดียวกับ /account)
พนักงานเห็นแค่: ชื่อลูกค้า / สินค้า / จำนวน / วันที่ — **ไม่มีตัวเลขเงินอยู่ในฐานข้อมูลนี้เลย**
(สคริปต์ import อ่านเฉพาะคอลัมน์ A, C, I, J, K — คอลัมน์เงินไม่ถูกอ่านออกไป)

## Data flow
Google Sheet (เครื่อง Pist) → `lucerna_push.py` → Worker `lucerna-ship` (D1) → หน้า /ship
พนักงานไม่แตะ Google Sheet — คนละฐานข้อมูล คนละรหัส

## Deploy ครั้งแรก (ทำครั้งเดียว)
```
cd tools/ship-worker
wrangler d1 create lucerna-ship            # เอา database_id ไปใส่ wrangler.toml
wrangler d1 execute lucerna-ship --remote --file=schema.sql
wrangler secret put PIN                    # รหัสพนักงาน (หน้า /ship)
wrangler secret put IMPORT_KEY             # รหัสสคริปต์ import (ตั้งคนละตัวกับ PIN)
wrangler deploy
```
ถ้าชื่อ worker เป็น `lucerna-ship` บน account เดิม URL จะเป็น
`https://lucerna-ship.lekvtwin.workers.dev` ตรงกับที่ hardcode ไว้ในหน้า /ship และ
`lucerna_push.py` แล้ว — ไม่ต้องแก้อะไร ถ้า URL ต่างจากนี้ แก้ค่า `API.url` ใน
`/ship/index.html` และ `WORKER_URL` ใน `lucerna_push.py`

## ใช้งานประจำวัน (ฝั่ง Pist)
```
python lucerna_push.py                # ส่งออเดอร์ของวันนี้เข้าเว็บ
python lucerna_push.py 25/8/2026      # ส่งเฉพาะวันที่ระบุ
python lucerna_push.py 25/8/2026 -    # ส่งตั้งแต่วันนั้นถึงวันนี้ (รันซ้ำได้ ไม่ซ้ำ ไม่ทับสถานะส่งแล้ว)
```
วางไฟล์ไว้โฟลเดอร์เดียวกับ `service_account.json` (ตัวเดียวกับ LucernaOne)
ระบบมี guard: ไม่ import ก่อน 25/8/2026 เด็ดขาด (START_DATE ในไฟล์)

## ฝั่งพนักงาน
1. เปิด `/ship` ใส่ PIN ครั้งแรกครั้งเดียว
2. แท็บ **จับคู่ EMS**: วางลิสต์จาก ปณ → กด "ตรวจ + จับคู่"
   - เขียว = จับคู่อัตโนมัติ (ชื่อตรง/ชื่อขึ้นต้นตรงแบบไม่กำกวม) — ติ๊กออกได้ถ้าผิด
   - เหลือง = เจอหลายคน ให้เลือกเอง
   - แดง = ไม่เจอคู่ → เลือกจากค้างส่ง / เก็บเป็นเลขลอย / ตัดทิ้ง
   - ไม่เลือกอะไร = เก็บเป็นเลขลอยอัตโนมัติ (ไม่มีเลขหายเงียบ)
3. แท็บ **ค้างส่ง**: ออเดอร์ที่ยังไม่มีเลข (ทุกวันรวมกัน เก่าสุดก่อน) — ใส่เลขเองได้
4. แท็บ **เลขลอย**: เลขที่ยังไม่มีเจ้าของ รอจับคู่ทีหลัง หรือตัดทิ้ง

## หลักการจับคู่ (precision ก่อน recall)
auto-match เฉพาะ 2 กรณี: ชื่อ normalize แล้วตรงเป๊ะ หรือฝั่งหนึ่งเป็น prefix ของอีกฝั่ง
(ปณ ชอบตัดท้ายชื่อ) *และ* มี candidate เดียวเท่านั้น — กำกวมเมื่อไหร่ โยนให้คนตัดสิน
normalize ตัด: คำนำหน้า (นาย/นาง/จ.ส.อ./ครู...), รูปบริษัท (บ./บจก./บริษัท/หจก. + จำกัด),
emoji, ช่องว่าง — "บ.เวโลคาเฟ่" จับ "บริษัท เวโลคาเฟ่ จำกัด" ได้

## อนาคต: คอลัมน์ K = ผู้รับ
แผน: ให้ parser ของ LucernaOne เก็บชื่อผู้รับจากบรรทัด "ถึง ..." ลงคอลัมน์ K อัตโนมัติ
(เคสใบกำกับภาษี: บัญชีลงชื่อบริษัท แต่กล่องจ่าหน้าชื่อคน) — สคริปต์กับ worker
รองรับ receiver ไว้แล้ว พอคอลัมน์ K มีข้อมูล การจับคู่เคสบริษัทจะ auto ได้ทันที
